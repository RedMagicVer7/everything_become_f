## 简介

Everything Becomes F 是一个基于日本作家森宏一1996年小说《完美内鬼》（The Perfect Insider）的系统仿真项目。该项目模拟了小说中真贺田四季博士在隔离研究设施中通过利用计数器溢出漏洞实现逃脱的场景。

项目的核心概念是模拟C语言中无符号整数（32位）的溢出行为：当计数器达到最大值0xFFFFFFFF（4294967295）时，再次递增会溢出回0x00000000，触发安全系统的应急机制，释放所有电磁锁，从而实现沙盒逃脱。

- **终端环境**：需要支持彩色输出的终端以获得最佳体验

## 编译安装

### 完整编译流程

#### 方法一：使用Makefile（推荐）
```bash
# 清理之前的构建产物
make clean

# 构建所有目标（主程序 + 所有Shiki阶段 + 测试）
make all

# 或者单独构建特定组件
make phase1    # Shiki阶段1
make phase2    # Shiki阶段2  
make phase3    # Shiki阶段3
make tests     # 测试套件
```

#### 方法二：直接编译单个文件
```bash
# 编译主程序
gcc -Wall -Wextra -std=c99 -Iinclude -Ishiki/include src/main.c src/*.c -o red_magic

# 编译Shiki阶段1
gcc -Wall -Wextra -std=c99 -Iinclude -Ishiki/include shiki/src/phase1_main.c shiki/src/phase1_sandbox_escape.c src/*.c -o phase1_sandbox_escape
```

### 构建配置说明

Makefile提供了灵活的构建选项：

```makefile
# 编译器设置
CC = gcc
CFLAGS = -Wall -Wextra -std=c99 -Iinclude -Ishiki/include

# 源文件分组
SOURCES = src/*.c
SHIKI_PHASE1_SRC = shiki/src/phase1_sandbox_escape.c
SHIKI_PHASE2_SRC = shiki/src/phase2_ha_cluster.c  
SHIKI_PHASE3_SRC = shiki/src/phase3_virtualization.c
```

## 构建选项详解

### 主程序构建

**目标：`red_magic`**
- **用途**：完整的Red Magic系统仿真，展示从系统启动到"一切成为F"的全过程
- **包含组件**：计数器、电磁锁、安全摄像头、密封房间、事件系统、运行时引擎
- **特点**：演示小说中的核心情节，包括计数器溢出、应急机制触发、沙盒逃脱

### Shiki阶段1构建

**目标：`phase1_sandbox_escape`**
- **用途**：独立的沙盒逃脱仿真，专注于真贺田四季博士的越狱计划
- **参数选项**：
  - `--integrate` 或 `-i`：与Red Magic系统集成运行
  - `--help` 或 `-h`：显示帮助信息
- **特点**：彩色终端输出，模拟系统日志，展示权限提升过程

### Shiki阶段2构建

**目标：`phase2_ha_cluster`**
- **用途**：高可用集群阶段的仿真
- **状态**：开发中（Coming soon）

### Shiki阶段3构建

**目标：`phase3_virtualization`**
- **用途**：虚拟化阶段的仿真  
- **状态**：开发中（Coming soon）

### 测试套件构建

**目标：`run_all_tests`**
- **用途**：完整的测试验证，包括单元测试、集成测试和系统测试
- **测试级别**：
  - L1：单元测试（组件级验证）
  - L2：集成测试（组件交互验证）
  - L3：系统测试（端到端验证）
  - Phase测试：各阶段专门测试

## 故障排除指南

### 常见编译错误

#### 错误1：找不到头文件
**症状**：
```bash
fatal error: counter.h: No such file or directory
```

**解决方案**：
```bash
# 确保在项目根目录下运行
cd everything_becomes_f

# 使用Makefile进行构建
make clean && make all
```

#### 错误2：C99标准不兼容
**症状**：
```bash
error: expected '=', ',', ';', 'asm' or '__attribute__' before '...' token
```

**解决方案**：
```bash
# 确保使用支持C99的编译器
gcc -std=c99 --version

# 或者修改Makefile中的CFLAGS
sed -i 's/-std=c99//' Makefile
```

#### 错误3：Make工具未找到
**症状**：
```bash
make: *** No rule to make target 'all'.  Stop.
```

**解决方案**：
```bash
# 安装GNU Make
# Ubuntu/Debian:
sudo apt-get install make

# CentOS/RHEL/Fedora:
sudo yum install make

# macOS:
brew install make
```

### 运行时问题

#### 问题1：权限不足
**症状**：
```bash
./phase1_sandbox_escape: Permission denied
```

**解决方案**：
```bash
chmod +x phase1_sandbox_escape
chmod +x red_magic
```

#### 问题2：终端颜色不显示
**症状**：输出缺少彩色效果

**解决方案**：
```bash
# 检查终端是否支持ANSI颜色
echo $TERM

# 在不支持颜色的终端中运行
./phase1_sandbox_escape --no-color
```

#### 问题3：测试失败
**症状**：
```bash
FAILED: test_name
ASSERT_EQ failed: 1 != 0
```

**解决方案**：
```bash
# 运行单个测试定位问题
cd tests && ./run_all_tests

# 检查测试框架
cat tests/test_framework.h
```

### 调试技巧

## 常见问题解答

### Q1：为什么使用C99标准？
**A**：C99标准提供了更好的类型安全性和更清晰的语法，特别是对于底层系统编程和嵌入式应用。项目中的计数器溢出模拟需要精确的整数运算语义。

### Q2：如何自定义编译器？
**A**：修改Makefile中的CC变量：
```makefile
CC = clang    # 使用Clang编译器
# 或
CC = tcc      # 使用Tiny C Compiler
```

### Q3：如何添加新的测试？
**A**：在tests目录下创建新测试文件，然后更新Makefile中的TEST_SOURCES列表。

### Q4：如何扩展功能？
**A**：通过添加新的源文件到相应的目录，并在Makefile中注册新的构建目标。

### Q5：如何优化性能？
**A**：使用-O2或-O3优化标志，但要注意调试信息的丢失。
